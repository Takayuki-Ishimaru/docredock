# DocRedock v0.2.12 Public Beta リリースノート

v0.2.12は、PDFの文字化けと一部の変換エラーを修正する更新です。表示範囲の完全に外側にある文字や、非表示と判定できたレイヤーの文字を既定の出力から除外します。照合画面では赤い強調表示を消して原本を確認できるようにしました。非表示判定の対象外となる文字については、後述の「利用上の制約と注意点」を参照してください。

## 主な改善

- **フォントを、使われている場所ごとに正しく変換**: PDFのフォントを、そのフォントを使うページや描画部品（Form XObject）のリソース辞書で解決します。これまでは、ページとFormが同じ名前（`/F1`など）で別々のフォントを使うと、すべてが1つのフォントの文字として変換され、警告も出ませんでした（v0.2.11以前から発生していた問題です）。リソース辞書に直接書かれたフォントも、それぞれの文字の対応表で変換します。
- **フォントを特定できない文字は推測しない**: 使われている場所でフォント名が定義されておらず、文書内で同じ名前が異なる文字対応のフォントに使われている場合は、どれかを推測して文字を置き換えません。読み取れた文字列をMarkdownに残し、`PdfFontResourceAmbiguous`警告を出して要確認ページにします。原本と照合してください。
- **表示範囲外・非表示レイヤーの文字を既定の出力から除外**: Form XObjectの表示範囲（`/BBox`）、クリッピングパス、ページの表示範囲の完全に外側にあると判定した文字と、文書を開いたときに非表示と判定できたレイヤー（Optional Content）の文字を、Officeの非表示文字と同じく非表示の内容として扱います。既定の`visible`と`sanitized`では出力せず（CLIでは`PdfClippedTextExcluded`／`PdfHiddenLayerTextExcluded`として件数を表示）、`complete`では警告付きで出力します。表示範囲に一部でもかかる可能性がある文字は出力に残します。表示状態を判定できないレイヤーの文字は出力したうえで、`PdfLayerVisibilityUnknown`警告と要確認ページにします。
- **照合画面の強調表示を切り替え**: 「強調表示」のチェックを外すと赤い線と枠が消え、原本の細部を確認できます。赤い線と枠は、拡大しても画面上の太さが変わりません。
- **除外した非表示の内容を結果画面に表示**: 内容ポリシーで除外した非表示の内容（Wordの非表示文字、PDFの表示範囲外の文字など）の種類と件数を、GUIの結果画面に表示します。
- **一部のPDFで変換が内部エラーになる問題を修正**: 1つの字形が複数の文字に対応するフォント（LibreOfficeが出力する合字など）を含むPDFで、変換が内部エラーで終了していた問題を修正しました。
- **実験的な新規文書生成の修正**: `render`の`--font-path`と`--font-face-index`が受け付けられなかった問題を修正しました。

## 更新方法

1. DocRedockを終了し、編集中の原本を保存してください。
2. OSとCPUに合うv0.2.12の配布ファイルをダウンロードし、`SHA256SUMS`で照合して、新しいフォルダーへ展開してください。
3. 同梱の`QUICKSTART.ja.md`に従って起動してください。OCRやPDF rasterizerの利用環境は、CLIの`doctor`コマンドで確認できます。

Windows、macOS、Linuxのx64／ARM64向けにGUIとCLIを配布します。

## 利用上の制約と注意点

- Public Betaです。対応範囲は[対応機能](../docs/ja/supported-features.md)と[利用ガイド](../docs/ja/user-guide.md)を参照してください。任意のPDF図形や工程表を完全に再構成できるわけではありません。
- PDFの表示・非表示の判定は文字が対象です。図形や画像のクリップ、図形の下に隠れた文字、背景と同じ色の文字、描画モードで不可視にした文字（OCR済みPDFの透明テキスト層を含む）、表示範囲に一部だけかかる文字のはみ出した部分は判定しないため、画面に表示されない文字が出力される場合があります。
- Excelの印刷のように列が複数のページに分かれたPDFでは、各ページの表示範囲の完全に外側と判定した文字（隣のページで表示される文字の重複など）を、`visible`／`sanitized`で出力しなくなります。これらの文字も必要な場合は`complete`を選択してください。
- 閲覧用Markdownは一方向の出力です。未解決の警告や解析できなかった内容がある場合は、照合画像や元文書を確認してください。画像を添付しても警告は解消されません。
- 照合画面の原本ページ画像はPDFが対象で、書き出し時に添付された照合画像が必要です。画像がない場合やOffice文書の場合は、案内に従って元文書を確認してください。PDFページの画像化にはPDF rasterizer、OCRには利用可能なOCRエンジンが必要です。Tesseract、追加のOCR言語データ、pdftoppm／mutoolは同梱しません。
- 照合画面の「表示」は確認用の簡易表示です。Mermaidの図は接続の一覧として示し、読み取れない図はソースのまま表示します。
- 変換状況の表示は、DocRedockが認識・解析した内容についての案内です。元文書のすべての見た目や意味が保持されたことを保証するものではありません。
- GUIのPDF入力は既定で利用できます。CLIのPDF変換、往復編集、復元前チェック、復元、新規文書生成は実験機能で、`DOCREDOCK_ENABLE_EXPERIMENTAL=1`による有効化が必要です。[実験機能](../docs/ja/experimental-features.md)を参照してください。
- 元文書を正本として保持してください。サイドカーや原本照合用画像には元文書の内容が含まれます。共有時の扱いは[セキュリティとプライバシー](../docs/ja/security-and-privacy.md)を参照してください。
- 配布ファイルの署名状態は、各パッケージ直下の`SIGNING-STATUS.json`を確認してください。
