# DocRedock v0.2.8 Public Beta リリースノート

v0.2.8 は、PDF工程表の読み取りと、変換結果を原本と照合するための表示を改善する更新です。実験的な復元機能には、復元前チェックと元文書の保護を追加しました。

## 主な改善

- **PDF工程表の行・列を保持**: 表に重なる長い塗りつぶしバーを罫線と誤認し、行や列が分割される問題を改善しました。対応するバーは、引き続き表のセル内に記号として表示します。
- **PDFの矢印方向を保持**: 線と矢印の先端が別々の図形で描かれた工程表でも、対応する矢印をまとめて認識し、余分な行や不完全な矢印表示を抑えます。
- **警告付き完了を明確に表示**: GUIで正常完了・警告付き完了・失敗を区別します。警告がある場合は、保存の完了と原本照合が必要なことを結果画面に表示します。表や図として解決できた内容の不要な警告を減らし、未解決の内容に関する警告は残します。
- **原本照合用のPDFページ画像**: 未解決の表・図があるページは、利用可能なPDF rasterizerで画像化して添付します。OCRがオフでも利用でき、GUIの設定またはCLIの `--pdf-fallback-images auto|off` で切り替えられます。既定は `auto` です。画像を生成できない場合は診断で知らせます。
- **OCR結果の確認を支援**: OCRエンジンが返す単語・行の信頼度と位置を表示し、原画像と比較しやすくしました。識別子、品番、数値を自動修正することはありません。
- **実験的な復元前チェック**: `docredock preflight edited.md` で、整合性・編集内容・復元可能性をまとめて確認できます。コピー上で復元を試すため、入力文書や既存レポートは変更しません。
- **実験的な復元で元文書を保護**: 履歴上の元文書を復元先に指定した場合、通常の `--force` だけでは上書きできなくなりました。意図的に置き換える場合は `--force --replace-original` が必要です。復元に成功した後、置換直前のファイルを `.bak` に保存してから置き換えます。通常は別名の出力先を使用してください。

## 更新方法

1. DocRedockを終了し、編集中の原本を保存してください。
2. OSとCPUに合うv0.2.8の配布ファイルをダウンロードし、`SHA256SUMS`で照合して、新しいフォルダーへ展開してください。
3. 同梱の `QUICKSTART.ja.md` に従って起動してください。OCRやPDF rasterizerの利用環境は、CLIの `doctor` コマンドで確認できます。

Windows、macOS、Linuxのx64／ARM64向けにGUIとCLIを配布します。

## 利用上の制約と注意点

- Public Betaです。対応範囲は[対応機能](../docs/ja/supported-features.md)と[利用ガイド](../docs/ja/user-guide.md)を参照してください。すべての工程表やPDFのレイアウトを認識できるわけではありません。
- 閲覧用Markdownは一方向の出力です。表内の記号や照合用画像は、元の図形・配置を完全に再現するものではありません。画像を添付しても未解決の警告は残るため、元文書と比較してください。
- PDFページの画像化にはPDF rasterizerが、OCRには利用可能なOCRエンジンが必要です。Tesseract、追加のOCR言語データ、pdftoppm／mutoolは同梱しません。OCRの位置リンクによる領域表示は閲覧ソフトの対応に依存します。
- GUIのPDF入力は既定で利用できます。CLIのPDF変換、往復編集、復元前チェック、復元、新規文書生成は実験機能で、`DOCREDOCK_ENABLE_EXPERIMENTAL=1` による有効化が必要です。復元前チェックの成功は、元文書との外観の一致を保証するものではありません。[実験機能](../docs/ja/experimental-features.md)を参照してください。
- `.drmd`／`.drmdpkg`には元文書や復元用データが含まれる場合があります。新しく作るサイドカーは元文書のローカル絶対パスも保持します。元文書と同じ機密区分で扱い、共有前に確認してください。旧サイドカーで、元文書を別名・別場所へ移して内容も変更した場合は、元文書と識別できないことがあります。[セキュリティとプライバシー](../docs/ja/security-and-privacy.md)を参照してください。
- 配布ファイルの署名状態は、各パッケージ直下の `SIGNING-STATUS.json` を確認してください。
