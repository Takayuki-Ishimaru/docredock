# セキュリティとプライバシー

日本語 | [English](../en/security-and-privacy.md)

## ローカル処理と更新確認

組み込み変換はローカルで動作します。文書をアップロードせず、文書内の外部URLを取得せず、表計算の数式を実行せず、任意のプラグインを自動探索しません。

GUIは公開GitHub Releases APIへ短いHTTPSリクエストを送る場合があります。文書内容、ファイル名、ローカルパスは送らず、更新を自動インストールしません。起動前に`DOCREDOCK_DISABLE_UPDATE_CHECK=1`を設定すると通信を無効化できます。

## 非表示情報と共有

閲覧用出力の既定値`visible`は、認識できるOfficeの非表示テキスト、非表示／veryHiddenシート、非表示行・列、非表示スライド・オブジェクト、ノート、コメント、変更履歴のメタデータと、PDFで表示範囲（Formの`/BBox`、クリッピングパス、CropBox）の完全に外側にある文字や、文書を開いたときに非表示のレイヤーの文字をMarkdown投影から除外します。`sanitized`はさらにメタデータ、派生・OCR情報、ヘッダー等を除外します。外部の`.assets/`には、選択ポリシーで含まれるノードから参照される画像だけを出力します。

`complete`は意図的に非表示情報とメタデータを含め、`HiddenContentIncluded`警告を出します。出力を機密情報として扱い、共有前に確認してください。可視性情報の表現はOffice文書の作成ソフトによって異なり、PDFでは図形の下に隠れた文字、背景と同じ色の文字、描画モードで不可視にした文字、表示範囲に一部だけかかる文字のはみ出した部分を判定しないため、どのポリシーも人による確認の代わりにはなりません。

`.md`と`.assets/`の両方に加え、埋め込みdata URI、保存済み計算結果、OCR出力も確認してください。実験用の`.drmd`と`.drmdpkg`は元文書バイナリや復元情報を含む場合があり、元文書と同じ機密区分で扱う必要があります。

AI向けパッケージには変換した本文・画像、元ファイル名とハッシュ、出典、確認事項を含めます。元文書、元ファイルの絶対パス、復元用サイドカーは同梱しません。内容ポリシーを全体に適用しますが、`complete`には非表示内容が含まれる場合があります。共有前に`document.md`、`assets/`、`review.md`を確認してください。生成したパッケージはアップロードされません。

Wordの変更履歴は`--revisions final|markup|reject`（GUIの「Wordの変更履歴」、APIの`Revisions`）で指定します。`final`は挿入後・現在の内容だけを出力し、削除内容・移動元・履歴注記を除外します。`markup`は削除内容も含む履歴付き表示、`reject`は変更履歴がある文書の書き出しを拒否します。省略時は`sanitized`が`final`、`visible`／`complete`が従来互換の`markup`です。`sanitized`で`markup`を選ぶ場合は`--allow-revision-sharing`またはGUIの許可チェックが必要です。許可チェックは保存されません。履歴付き出力は共有確認対象となり、`--fail-on-review`で終了11になります。原本と復元用サイドカーには履歴が残ります。

`report.json`の`sharing_review`で履歴の包含と共有確認を判定できます。旧パッケージでも変更履歴の診断があれば現在のリーダーは確認を要求します。

## 信頼できない入力

DocRedockはXML DTD、アーカイブtraversal／過大展開、symlink escape、不審な数式、対応外の保護構造を検査します。主な上限は元文書200 MiB、Markdown 16 MiB、検証済み埋め込み画像1件10 MiB／合計50 MiBです。

信頼できない文書は隔離した利用者権限で処理し、組織のマルウェア対策を適用してください。

## 出力パスの保護

CLIの各コマンドは、`--output`（または出力先）が自分自身の入力ファイルと同一のファイルを指す場合——同一パス、大文字小文字だけが異なるパス（macOS/Windowsなど大文字小文字を区別しないボリューム）、シンボリックリンク、または同一実体と識別できるハードリンク——を`--force`指定時でも拒否します。`--force`は既存の古い出力を置き換えるためのものであり、コマンド自身の入力文書を上書きすることを許可するものではありません。衝突する出力はexit code 2で失敗し、何も書き込みません。

## 脆弱性を報告する

機密報告や実文書を公開Issueへ投稿しないでください。[SECURITY.md](../../SECURITY.md)に従い、機密情報のない最小の合成再現例を使用してください。

v0.2.8では、復元時に履歴上の元文書も保護します。新しいサイドカーは`source.original_path`に元文書のローカル絶対パスを保持します（ネットワーク送信はしません）。共有時には、このパス情報も含まれることに注意してください。復元先がそのパス・同一実体、または元文書と同じSHA-256なら`--force`だけでの置換を拒否し、`--replace-original`と保持バックアップを必要とします。旧サイドカーはMarkdownと同じフォルダーの元ファイル名とSHA-256で判定します。パス情報のない旧原本を別名・別場所へ移し内容も変更した場合は識別できません。現在の入力Markdownとサイドカー内部の原本は専用オプションでも上書きできません。
