# DocRedock 利用ガイド

日本語 | [English](../en/user-guide.md)

このガイドは、v0.4.1 Public BetaのデスクトップGUIで、DOCX／XLSX／PPTX／PDFを**閲覧用Markdown**、**閲覧用HTML**、**AI向けパッケージ**にローカルで変換する方法を説明します。

[目的別クイックガイド](quick-tasks.md)

## 1. 入手する

OSとCPUに合う配布物を選び、公開されたSHA-256を確認します。展開したアプリは別途.NET SDKを入れずに起動できます。[ダウンロードと起動の案内](../../release-docs/RELEASE_NOTES_v0.4.1.md#ダウンロードと更新)

## 2. 変換する

1. DocRedockを起動します。
2. DOCX、XLSX、PPTX、PDFのいずれかを選択またはドロップします。
3. **閲覧用Markdown**を選びます。
4. 特別な目的がなければ**表示中の内容（推奨・変更履歴は印付き）**のままにします。
5. 図の接続推定は、特別な目的がなければ**Safe（推奨）**のままにします。
6. 出力先を選んで変換し、Markdown、診断、assetを確認します。

デスクトップGUIはPDFを既定で受け付けます。ネイティブテキストとベクター図形だけのページにはOCRを行いません。OCRにはproviderが必要で、画像だけのページにはPDF rasterizerも必要です。OCRを有効にすると、同じページにネイティブテキストがあっても、埋め込み画像を個別に切り出して認識します。照合用に添付するページ画像は比較専用で、OCRには渡しません。必要なproviderが利用できない場合は、ページplaceholderと診断を確認してください。

PDFの読み順と段落の結合は、測定位置を使って慎重に判断します。枠のない本文行は、実測字幅・文字サイズ・基準線の間隔と揃い方から続きの行と判断できる場合だけ、折り返し段落に結合します。フォント字幅が不明、等幅フォント、見出し、リスト境界、表、図のラベルは結合しません。段組みとして読むのは、3行以上にわたって実測できる段間の余白が続く場合だけです。TrueTypeの字幅が分かる場合は、6～8mm程度の狭い余白も段間として扱えることがあります。1行だけの大きな空白は段の境界にしません。枠やカードは箱ごとに左から右、上から下へ読み、ラベルと値が並ぶ欄、罫線が横切る帳票、グラフ、図は検出された読み順を保ちます。罫線から明確な矩形格子を確認できる場合は、列幅が不均等でも、矩形の行・列結合を持つ表を再構成できます。曖昧な格子は推定として扱い、確認が必要な場合があります。全文の閲覧用Markdownでは、隣接ページの端で同じ列構成の表に繰り返し見出しがあり、重なる図形や変更印付きセルがない場合に限り、表を次ページへ継続します。AI向けパッケージの`document.md`にもこの継続表示が適用されますが、分割本文は引き続きPDFのページ単位です。再構成した表の外にある本文は保持し、説明できない欠落は`PdfNativeTextUnaccounted`で報告します。

CLIのPDF変換（export）は`--allow-pdf`または`DOCREDOCK_ENABLE_EXPERIMENTAL=1`で有効にできます。復元・生成（render）など、ほかの実験的CLIワークフローには引き続き`DOCREDOCK_ENABLE_EXPERIMENTAL=1`が必要です。読み取り専用の`docredock inspect <file.pdf>`は設定なしで利用できます。

CLIの既定も閲覧用Markdownです。

```sh
docredock export input.docx --content-policy visible --visual-inference safe --output input.md
```

`native-only`は元形式に明示された接続だけを使います。`safe`は一意なhigh-confidence geometry割当を昇格します。`balanced`はmedium-confidence割当も対象にできますが、同率・矛盾・graph全体で曖昧な関係は引き続き未解決にします。

実験的なサイドカー往復処理を使う場合だけ`--profile roundtrip`を明示します。

Excelの閲覧用Markdownには、元ブック名・シート名・セル範囲と、各シートへ移動する目次を付けます。`--no-source-references`、`--no-table-of-contents`でそれぞれ省略できます。表の出力は`--table-layout auto|grid|records`で選択します。既定の`auto`では10列を超える表をレコードごとの項目一覧にし、長い説明を読みやすくします。`grid`は表形式、`records`は項目一覧を指定します。数式は既定で保存済み計算値を表示し、`--show-formulas`では数式もコードとして表示します。保存済み計算値がないセルにはその旨を表示します。パイプ記号を含む数式は、Markdown処理系による表の解釈の違いを避けるため項目一覧へ切り替えます。AI向けパッケージの行ブロックは通常の表形式を維持します。

通常の閲覧用出力では、Excel・Word・PowerPoint・PDFの表上の図形注記を値に混ぜず、元セル範囲を示す別の注記にします。元の配置は要確認として通知します。MarkdownではAPIの`SeparateWorksheetAnnotations: false`を指定でき、低水準のMarkdownシリアライザー・AI向けパッケージも従来のセル内記号表現を使えます。HTMLでは注記を常に分離します。有効な複数行JSONの例は、通常の閲覧用Markdownでは字下げを保つコードブロックにします。Markdownの表・見出しの推定は元のExcel構造との完全一致を保証しないため、正確な行列対応の確認にはHTMLの元セル参照も使ってください。

多段の列見出しは各行の列名・強調・結合範囲を確認してまとめます。後方に数値行があるだけで、途中の項目名・属性・桁数を列見出しへ取り込むことはありません。状態・更新日と本文は元の位置で出力し、同じ範囲の新しい節見出しを越えて本文を前の表へ戻しません。離れた列の独立した注記は本文と連結せず、列間隔の広い表を保つ判定も連続した局所範囲に限定します。

## 閲覧用HTML

閲覧用の出力は、Markdownの代わりに**HTML**でも書き出せます。1つの`.html`ファイルだけで完結し、どのブラウザーでも開け、そのまま1ファイルで共有できます。GUIでは「閲覧用Markdown」「AI向けパッケージ」「往復」と並ぶ「閲覧用HTML」を選びます。このとき画像の埋め込みは常にオンで、変更できません。

HTMLはMarkdownを経由せず、各形式から読み取った共通の文書モデルを、見出し・文字列・表・画像などの型付き構造へ投影して直接生成します。Markdownは同じ元データから別の出力処理で生成します。このため、HTMLのセル結合や書式がMarkdownの表現能力に制限されず、元の文章に含まれる`$`・パイプ・バッククォートなどもMarkdown記法として解釈されません。

```sh
docredock export report.xlsx --format html --content-policy visible
docredock export slides.pptx -o slides.html
```

- 画像はdata URIとして埋め込むため、`.assets`フォルダーは作りません。Mermaid図（フローチャート・シーケンス図）は外部ツールなしでインラインSVGに描き、ソースを折りたたみ式のブロックに残します。描けない図はソースと代替情報を残します。節への目次と、アクセシビリティ用の表見出しを付けます。
- Word・Excel・PowerPoint・PDFの表の結合セルを`rowspan`／`colspan`で保持し、入れ子の表も構造として出力します。巨大な疎行列など、安全に表へ展開できない範囲は項目一覧に切り替え、診断を残します。
- Excelでは元の列幅の比率・行高・文字色・セル背景・罫線・文字配置を反映し、固定行・列をスクロール時にも表示します。元の配色／ライト／ダークを選択でき、既定は元の配色です。数値は元の配置指定がなければ右寄せにします。列の多い表は画面全体で横へスクロールでき、目次は狭い画面では本文の上に表示します。
- Excelの保存済み計算値を表示し、`--show-formulas`では数式も表示します。再計算はせず、計算値が欠ける場合は明示して診断します。元ブック・シート・セル範囲を参照表示とHTML属性に残します。未対応の条件付き配色・アイコン・データバーなどは診断の対象です。
- Excelの用紙・縦横方向・余白・印刷範囲・印刷タイトル・手動改ページを印刷用CSSへ反映します。画面でダークを選んでも印刷は明るい背景と元のセル配色になります。ブラウザーのフォント計測や改ページに従うため、Excelとの完全一致や倍率・縦方向のページ数指定は保証しません。
- 空欄の行・列と結合範囲を保持し、巨大な行の空きが省略された場合は元行番号と診断を残します。元にない交互の行色を加えず、透明画像は白背景で表示します。
- Excelに保存された外部ハイパーリンクと、URLを直接書いた`HYPERLINK`数式をリンクとして保持します。普通のURL文字列は自動でリンクにしません。HTMLでは結合セルの継続部分を含むセルへの内部リンクを解決し、絞り込みで隠れた移動先も表示します。未出力・未対応の移動先は通知します。動的なリンク数式の再計算は行いません。
- 接続線の両端の矢尻を読み取り、両方向・片方向・方向なしを区別します。両方向のシーケンス図など対応できない図は、片方向へ置き換えず代替情報と要確認を残します。
- Excelの元印刷ページではヘッダー／フッターの文字・書式・ページ番号を保持します。Word・PowerPoint・PDFでは保存されたヘッダー／フッターの文字を開いた参照欄に保持します。再組版したHTMLで元の物理的なページ位置やフィールドの再計算は再現しません。`sanitized`ではこれらを意図的に除外します。セルのメモと著者はMarkdownとHTMLで同じ内容ポリシーに従い、`complete`だけで出力します。
- Wordの表内画像とリンクは元のセルとの対応を保持します。HTMLでは表示幅に合わせて画像を縮小する際も、画像データ本来の比率とは異なる元の描画枠の縦横比を保持します。PowerPointとPDFのリンクは表セル内も含めてリンク対象の文字に付けます。PDFの完全にクリップ範囲外の画像や非表示レイヤーの画像は通常の内容ポリシーで除外します。画像の部分的なクリップは再現しません。
- ネットワークから何も読み込みません。ExcelのHTMLだけに、検索・行列フィルター・表示列・固定列・シート移動と印刷用の固定スクリプトを含め、Content-Security-Policyでハッシュが一致するものだけを許可します。元文書が実行コードを渡すことはできません。他の形式はスクリプトを含みません。
- 内容ポリシー、変更履歴、シート、OCR、図の接続推定、言語、タイトルの設定は、Markdownと同じように働きます。
- `--table-layout`・`--no-source-references`・`--no-table-of-contents`はMarkdown用です。HTMLは元の表構造・参照情報・目次を使い、GUIの結合値の繰り返し設定も適用しません。
- ブラウザーで表示できない画像（EMF／WMF／TIFF）や、サイズ上限（1枚25 MiB、合計200 MiB）を超える画像は、説明文に置き換えて警告（`HtmlImageNotEmbeddable`、`HtmlImageEmbedSkipped`、`HtmlImageMissing`）で報告します。
- HTMLは一方向の出力です。Officeへ復元することはできず、AI向けパッケージでもありません。

CLIでは`--format markdown|html`を指定します（`md`も使えます）。`docredock export input.docx --format html`は`input.html`を書き出し、`--format`を省略して`--output`が`.html`で終わるときもHTMLになります。`--images embed`（HTMLの既定）または`omit`を選べ、HTMLで`--images files`は指定できません。`--ai-package`、`--profile roundtrip`／`audit`とは併用できません（終了コード2）。`--output-dir`による一括変換（入力ごとに1つの`.html`）と、`--output -`（標準出力へHTML）にも対応します。`--json`の結果には`"output_format": "markdown" | "html" | "ai-package"`が付きます。MCPサーバーの`export_html`ツールも同じ変換を行います（[目的別ガイド](quick-tasks.md#mcpクライアントから使う)を参照）。

### 図形とPDFの原本表示

Wordの組版、3D、描画エンジンに依存するSmartArtには、HTMLの`--office-layout auto|source|structured`を使えます。`auto`は利用可能なローカルLibreOfficeで必要な原本ページを描画し、`source`はその経路を必須に、`structured`はSVG/CSSによる構造化表示に固定します。`DOCREDOCK_OFFICE_RENDERER`にローカルの`soffice`実行ファイルを設定するか、アプリ隣の`office/program`へ配置します。PDF rasterizerも必要です。変換時の自動ダウンロード・インストールは行いません。

原本ページ表示は、用紙・余白・段組み・改ページ・印刷ヘッダー／フッターをローカルで描画した画像として保持し、ページの抽出テキストと構造化本文を別欄に残します。原本は変更せず、一時コピーからマクロ・外部データ接続・外部リンクを除き、外部の内容を取り込むWordフィールドは保存済みの結果に置き換え、Excelは保存済み計算値を使います。`sanitized`／`complete`、画像省略、シート指定、変更履歴付き表示には適用しません。ローカルエンジンがSmartArtの文字を欠落させた場合などは通知し、不完全なページを正常扱いしません。描画エンジンとフォントによるMicrosoft Officeとの差は残るため、ピクセル単位の一致を保証するモードではありません。

閲覧用HTMLの図形は、ExcelのシートとPowerPointのスライド、Wordの図の枠の中で元座標を保持します。標準187図形、調整値とガイド式、ベジェ曲線・円弧、パスごとの塗りと線、テーマ色・線形グラデーション、段落・文字ごとの装飾、グループの拡大率・回転・反転・重なり順をSVG/CSSへ反映します。scRGB・HSL・定義済み色にも対応し、反転した図形内の文字は鏡像化しません。日本語などの東アジア文字と複雑文字用の書体、テーマの言語別書体を保持しますが、実際の描画には端末のフォントが必要です。Wordの単独画像も切り抜き・回転・反転がある場合は図の枠で保持します。Wordのインライン枠とページ／段落基準の枠は区別し、ブラウザーでWordの本文ページ割りを再計算するものではありません。縦書き・文字の独立回転・upright配置を保持します。未対応の形状・効果、放射状グラデーション、文字ワープには出典付きの確認事項を残します。

保存済みデータのある棒・折れ線・面・円・ドーナツ・散布図を直接描画します。棒・折れ線・面グラフの積み上げ・100%積み上げと明示された軸範囲を保持し、元の数値は変更しません。複合グラフは、棒・折れ線・面・散布図のグループを1つのプロットエリアに描画し、グループごとに系列を並べ・積み上げ、第2数値軸を主軸の反対側に表示します。複合グラフの円・ドーナツのグループは他のグループの背面に独自の円として描画し、横棒に重ねた折れ線・面のグループは専用の数値軸を使って横方向に描画します。対数軸（目盛りは底の累乗。0以下の値は警告のうえ描画しません）、軸の反転、軸の交点、削除された軸、凡例の位置（右・左・上・下・右上）を反映します。横棒グラフの項目はExcelと同じく下から順に並べます。ドーナツは系列ごとに輪を描き、最初の系列を最も内側に置きます。円・ドーナツの負の値はExcelと同じく絶対値で描画し、0以外の値がない円グラフは凡例と注記を残します。基本データラベル（個別の要素のラベルと表示形式を含む）と値軸タイトル、折れ線・面グラフの空白表示設定に対応します。長い目盛りラベルや横棒グラフの長い項目名は、グラフ幅の40%までラベル領域を広げ、それを超える場合に省略します。プロットエリア・凡例・グラフタイトルの手動配置を反映します。系列・要素・グラフエリア・プロットエリアの単色・グラデーション・パターンの塗りを、テーマの色を含めて描画します。線・マーカー・文字のグラデーションは代表色1色になります。暗い背景ではグラフに指定された文字色でラベルを描画し、指定がない場合は警告のうえ明るい色で描画します。日付などの数値の項目名、軸の目盛り、データラベルは、セルと同じ規則でExcelの表示形式に従って表示し（日付は `yyyy-MM-dd`）、元の数値は変更しません。適用できない表示形式・特殊な軸タイトル配置・空白の表示設定などは通知します。外部データの取得や再計算は行いません。3Dの棒・折れ線・面・円グラフは、警告のうえ同じデータの2Dグラフとして平面に描画し、奥行きや遠近は再現しません。レーダーチャート（標準・マーカー付き・塗りつぶし）は極座標の軸で描画します。バブルチャートは各バブルの面積または幅を最大のバブルに対する比で描画し、負のバブルはグラフが表示する設定のときだけ描画します。株価チャートは高値-安値線、ローソク、終値の目印を描画し（単独、または第2軸で出来高の棒に重ねて）、系列自体の線とマーカーは描画しません。等高線グラフは2D・3Dとも上から見た図として、値の帯ごとに色分けしたセルの格子で描画し、帯を凡例に示します（ワイヤーフレームは帯の境界線のみ）。円グループ2つは横に並べ、円とドーナツのグループは同じ中心に重ね、補助円グラフ付き円グラフは1つの円として描画し、いずれも通知します。系列・要素・グラフエリア・プロットエリアの画像の塗り（引き伸ばし・並べて表示）と、系列・プロットエリアの外側の影を描画します。その他の効果は通知のうえ描画しません。他のグループと組み合わせたレーダー・バブル・等高線のグループ、他のグループと並ぶ複数の円グループ、横棒と散布図の組み合わせや横棒と同じ数値軸を使う折れ線、2Dグラフの3D書式は枠と保存済みデータを残して通知します。グラフのすべての装飾を再現するものではありません。

複雑なPDFの要確認ページは、rasterizerと照合画像が有効なら元ページ画像を先に表示し、抽出テキスト・構造をその下の説明欄へ分けます。曲線・クリップ・透明度はこの元画像で確認できます。これはベクター変換ではなく、解像度はrasterizer設定に従います。`sanitized`では除外した注釈や印刷情報が画素に残ることを防ぐため、元ページ画像を出力しません。

## Excelのレビュー用フォルダー

`docredock export report.xlsx --split-sheets -o report.review --ocr off`で、人が確認するためのフォルダーを出力できます。`README.md`から元シート名を含む連番の`sheets/*.md`へ移動でき、専用の履歴シートの全行を`CHANGELOG.md`へ保持します。画像は`assets/`へ分離して重複を除き、`layout.html`は元の文書モデルから直接描画します。`manifest.json`・`source-index.json`・`conversion-report.json`に、元ファイル、シート、セル範囲、認識数・選択数・ポリシーによる除外数、位置付きの警告と未対応機能を残します。件数の一致は、原本との完全一致を証明するものではありません。

CLI／APIで1つのXLSXを対象に使い、シート選択と内容ポリシーを適用できます。既存の出力先はCLIでは`--force`が必要で、APIは上書きしません。AI向けの分割パッケージとは別の出力です。Markdownはraw HTMLを使わないCommonMarkのレコード形式とし、複数行の内容は字下げを保つコードブロックにします。単一Markdownでも`--portable-markdown`で同じ方針を選べます。通常のMarkdownはGFMを対象とし、数式は数式拡張ではなくコードとして保護します。Mermaid非対応の表示環境でも、図のノードと接続関係を文字で読めます。色・罫線・配置・印刷は元配色のHTMLと照合し、色の意味を凡例なしで推測しません。

HTMLの検索・表操作はローカルで働き、元の値を変えず、印刷時には全行・全列を使います。「標準」は先頭8列を表示し、「全列」「リセット」で全体に戻ります。テーマ切替は周囲のUIに適用し、Excelのセルは元配色を維持します。図を含むシートは、セル・画像・対応するDrawingML図形を元の座標で表示し、グループの変換・回転・重なり順・矢印の先端を保持します。検索や絞り込み用のセル一覧も開けます。印刷は用紙・余白・印刷範囲・繰り返しタイトル・手動改ページを反映したページで行い、ヘッダー／フッターの左右中央の文字・書式・先頭／奇数／偶数ページ・ページ番号を保持します。シート単独印刷では総ページ数を再計算します。Markdownにも印刷文字列を残し、sanitizedでは除外します。未対応の図形形状・スタイル参照・図形内の書式・取得できないフッター画像は変換レポートに場所を示します。対応するグラフは保存済みデータから直接描画し、未対応のグラフは元の枠と保存済みデータを警告付きで保持します。再計算・入力規則の実行・アウトライン展開は行いません。抽出テキストのない画像は全文検索できないことを明示します。

## AI向けパッケージ

v0.4.1では、**AI向けパッケージ**を利用できます。GUIで「AI向けパッケージ」を選び、出力形式をフォルダーまたはZIPに設定します。対象内容、OCR、図の設定は閲覧用Markdownと共通です。書き出した内容と`review.md`を確認してからAIに渡してください。変換はローカルで完結し、パッケージの生成でファイルがアップロードされることはありません。

```sh
docredock export input.docx --ai-package dir --content-policy visible --ocr off
docredock export input.xlsx --ai-package zip --sheets Summary,Data --output workbook.ai-package.zip
docredock export input.docx --ai-package zip --chunk-chars 16000 --output input.ai-package.zip
docredock export input.xlsx --ai-package dir --table-row-blocks --output workbook.ai-package
```

概算トークン数に余裕を持たせる場合は、CLIで`--token-estimate-multiplier 2`を追加できます。倍率は1以上100以下、既定値は1です。本文や分割方法は変わらず、実際のtokenizerの値やトークン上限を保証するものではありません。GUIには倍率の指定操作はありません。

GUIの「パッケージを読む」から既存のフォルダー／ZIPを開き、検証と確認事項を確認してから、必要な分割を検索・コピーできます。CLIでも次の操作を利用できます。

```sh
docredock package search input.ai-package.zip "売上" --json
docredock package read input.ai-package.zip --part part-0002
docredock package read input.ai-package.zip --part part-0002 --json --with-sources
docredock package review input.ai-package.zip --json --require-hidden-review
```

`package review package.zip`はパッケージ全体を検証してから`review.md`だけを表示します。`--json`では変換確認、変更履歴の共有確認、非表示内容、停止理由、影響する分割IDとレビュー文書を取得できます。影響範囲を分割ごとに特定できない項目があるため、要確認時の分割IDはパッケージ全体を保守的に列挙します。この操作自体は通常終了0、`--fail-on-review`を付けると要確認時はレビュー情報を返して終了11です。

受信側でも非表示内容の共有確認を必須にするには、`package search/read`に`--require-hidden-review`を付けます。非表示内容を含む場合は本文を出さず終了11となり、確認後の`--allow-review`で解除できます。GUIでは「非表示内容を含むパッケージも共有範囲の確認後に読む」を選択します。古い`complete`パッケージで非表示内容のフラグがない場合も確認対象です。同梱Python readerには同名オプションがあり、全体検証を自動で有効にして本文出力前に終了3で停止します。確認後はこのオプションを外して読み取ります。

最終版のセル削除で表の列対応を確定できない場合、残存文字を行順に保持し、`DocxFinalTableGridUnresolved`診断と原本照合の確認事項を付けます。列見出しとの対応を推測した表にはしません。

この代替表示でも、表上の図形の文字はセルとの対応が不明な注記として保持します。結合セル1個と通常セル複数で同じ列を削除した場合は、削除範囲を同等に扱います。CLIのレビュー表示と単一分割読取は、他の分割本文をメモリに保持せず全体検証します。

Python readerの`--require-hidden-review`は既存の変換・共有確認も停止対象にします。JSONの`review.required`／`effective_required`は実効状態、`reported_required`は元の確認状態、`stop_reasons`は停止理由です。このオプションを省略した場合のJSON形式は従来どおりです。

どちらのCLI操作も本文を返す前にパッケージ全体を検証し、要確認の場合は本文を出さず終了コード11を返します。`review.md`と該当する内容を確認した後、1回の実行について確認済みとするには`--allow-review`を付けます。`--json --with-sources`で取得した元セル等の出典情報は手元に置き、AIには必要な本文だけを渡せます。検索は対応する装飾・エスケープ、大文字小文字、全角半角を正規化した文字列照合です。

GUIでは、パッケージの出力設定の近くで文字数目安とExcelの行分割を選びます。最初の文書のOCRなしの見積もりと、変換後の実際の分割数・最大文字数・目安超過・全文と分割合計の文字数を確認できます。すべての分割を合わせると、再掲した見出し等で全文より大きくなる場合があります。

Wordの変更履歴はGUIまたは`--revisions final|markup|reject`で選択します。CLI・GUI・APIのいずれも`visible`／`complete`の既定が履歴付き、`sanitized`の既定が最終版です。最終版の出力で除外した変更履歴は情報として記録します。`sanitized`の履歴付き出力には`--allow-revision-sharing`またはGUIでの共有確認が必要です。manifestは引き続きschema `2.2`、reportはschema `1.2`で共有確認の`sharing_review`を追加します。旧パッケージを扱う共有確認の連携では読み取り側も更新してください。

既定の出力名は`<元ファイル名>.ai-package`または`<元ファイル名>.ai-package.zip`です。

| ファイル | 内容 |
| --- | --- |
| `document.md` | 文書全体の閲覧用Markdown |
| `parts/0001.md`など | 元ファイル名とWordの見出し階層を添えた、意味のまとまりごとのMarkdown |
| `assets/` | 文書が参照する画像。分割Markdownからは`../assets/`を参照 |
| `review.md` | 変換の制約、OCR確認件数、非表示内容の注意、該当する分割へのリンク |
| `manifest.json` | 元ファイル名・ハッシュ、変換設定、分割ごとの出典、生成ファイルのハッシュ |
| `source-index.json` | 全ノードIDとExcelの元セル座標。詳細が必要なときに読み込む索引 |
| `report.json` | 変換結果と確認事項、診断コード・件数のJSON |

Wordは見出しと意味のまとまりで分割し、既定のサイズ目安は12,000文字です。表・入れ子の表、図と構成要素、連続するリストはまとめて保持します。PDFはページ、PowerPointはスライド、Excelはシートごとに保持します。大きい単位は目安を超える場合があり、`exceeds_target`と`review.md`に記録されます。文字数の目安であり、AIモデルのトークン上限ではありません。CLIでは`--chunk-chars`、APIでは`TargetCharacters`で128～1,000,000文字を指定でき、GUIの文字数目安でも同じ範囲を指定できます（既定は12,000文字）。各分割には、渡す量の見積もりに使える`estimated_tokens`も記録します。これはモデル非依存の概算で、通常のASCII文字（数字と`|`を除く）は約4文字につき1トークン、連続する数字はまとまりごとに3桁につき1トークン（まとまりごとに切り上げ）、Markdown表の区切り文字`|`は約2文字につき1トークン、ASCII以外のUnicodeスカラーは1つにつき1トークンとして数えます。通常のASCII文字と`|`は、それぞれ全体の件数を切り上げます。モデルのtokenizerで測定した値ではなく、正確なトークン数や上限内に収まることを保証しません。

大きなExcelの表は、任意で行の区切りで分割できます（既定はオフ）。CLIの`--table-row-blocks`、GUIの「大きなExcelの表を行ブロックに分割」、APIの`TableRowBlocks`で指定します。シートが目安を超えるとき、1つの分割に収まらない表を行ブロックに分けます。各ブロックは表の見出し行から始まり、分割と`manifest.json`に、表のID、何番目のブロックか、見出し行とそのブロックの行の元のセル範囲、前後の分割を記録します。表のすぐ上にある短いセルの文字（`売上実績（単位: 千円、税抜）`のような表題・単位・条件の注記）は最初のブロックに含め、2つ目以降のブロックでも見出し行の前にそのまま再掲します。1つのブロックだけをAIへ渡しても数値の意味がわかるようにするためで、分割と`manifest.json`（`context_range`）にそのセル範囲を記録します。行の重複・欠落・並べ替えは起きません。小さな表やほかの形式は従来どおりです。

簡潔なmanifestでは、実際のPDFページ番号、スライド番号、シート名、Wordの見出し階層を共有の出典情報として記録します。全ノードIDとExcelの元セル座標は別の詳細索引に保持します。Wordのページ番号は推測しません。空の単位や設定で全て除外された単位は分割を作りません。`visible`／`sanitized`／`complete`とシート指定は、全文、分割、出典、画像に共通して適用されます。`complete`には非表示内容が含まれる場合があり、共有前の確認を表示します。元のOffice/PDFファイルと元ファイルの絶対パスは同梱しません。

現在のmanifestはschema `2.2`です。v0.3.2の`2.1`（`table_row_blocks`と各分割の`estimated_tokens`・`table_block`）に、行ブロックの`context_range`を追加しました。読み取る側はメジャー番号で判定し、知らない項目は無視してください。v0.3.1のパッケージはschema `2.0`、v0.3.0は`1.0`です。APIの`AiPackageManifestReader`と、標準ライブラリだけで動くPythonの読み取り例[`docs/examples/ai_package_reader.py`](../examples/ai_package_reader.py)は、`1.x`と`2.x`を同じ形で読み、それ以外のschemaは明示的なエラーにします。どちらも読み取る前にmanifestを点検し（必須項目とその型、IDやZIP内の名前の重複、分割した表のブロックのつながり、参照するすべてのファイルがサイズとSHA-256付きで列挙されていること）、source-indexが各ノードを1つの位置・セルに対応づけていることを確かめ、manifestに載っていないファイルがパッケージにあれば報告します。Pythonの例は分割を出力する前にファイルを検証し（`--verify --part`）、`--json`を付けると検証済みの本文を元のセル・review状態と一緒に1回で返します（.NETでは`ReadVerifiedPartAsync`）。`--search`で語を含む分割を探せます。ハッシュの一致は書き出したときのまま改変されていないことを示すもので、変換内容が正しいことや共有してよいことを示すものではありません。変換結果では、Excelセルから組み立てた表を含め、Markdownに出力した表の件数も確認できます。件数は本文の意味や読み順の正しさを保証するものではありません。

AIへの依頼ごとに`document.md`と`source-index.json`の両方を渡す必要はありません。収まる場合は`document.md`、収まらない場合は分割を順に渡します（各分割に元ファイルと位置が書かれています）。`source-index.json`は手元に置き、回答をノードIDやExcelのセルへ戻すときだけ読み込みます。詳しくは[形式仕様](../reference/ai-package.md#giving-a-package-to-a-model)を参照してください。

画像は`assets/`へ保存するため、`--embed-images`とは併用できません。`--no-diagrams`、`--show-formulas`、`--ocr-review`、PDF照合画像など、既存の変換設定も利用できます。CLIのPDF変換は`--allow-pdf`または実験機能の環境変数で有効にします。変換にWarningがある場合は終了コード1です。失敗・キャンセル時は不完全なパッケージを残しません。自動処理では`--fail-on-review`を付けると、照合が必要な項目（原本照合ページ、OCR確認、Excelの表の区切り、Word変更履歴の共有確認。`report.json`の`review.required`）がある場合に、パッケージを書き出したうえで終了コード11を返します。終了コード0だけを見てAIへ渡してしまうことを防ぐためで、付けない場合は照合項目で終了コードは変わりません。CLIの既存出力の置換には`--force`が必要で、GUIの再実行は連番の名前を選びます。パッケージはAI入力向けの一方向出力で、復元用サイドカーとしては利用できません。APIとJSONの詳細は[形式仕様](../reference/ai-package.md)を参照してください。

## 3. 生成されるファイル

| 生成物 | 内容 | 現行での利用 |
| --- | --- | --- |
| `.md` | 本文、見出し、リスト、表、図のsemantic projection／注記／placeholder | 使用する |
| `.assets/` | Markdownから参照する画像、preview等のvisual fallback | 生成された場合に使用する |
| `.html` | 閲覧用HTML。画像とインラインSVGの図を埋め込んだ単一ファイル（`.assets/`なし） | 使用可。一方向で復元不可 |
| report／diagnostic | 未解決connector、partial projection、fallback、欠落理由等 | Warning時は必ず確認する |
| `.drmd` | 元文書／復元用サイドカー | 実験用。元文書と同じ機密区分で扱う |
| `.drmdpkg` | Markdownと復元情報のパッケージ | 実験用。元文書と同じ機密区分で扱う |

Mermaidは、接続関係が明確で矛盾しない場合だけ出力します。認識した図は、(1) Mermaid、(2) 画像／ページプレビュー等の代替表示、(3) 明示的な診断の順で、利用可能な形を残します。図形テキストがあることだけでは、接続関係や分岐まで完全に保持したことにはなりません。

GUIのパッケージ設定には、行分割、目安文字数、予想分割数、最大分割サイズと超過の有無を表示します（予想は先頭の文書・OCRなし）。書き出し後は実績を表示します。「パッケージを読む」でZIP／フォルダーを検証し、確認レポートを読んでから本文を検索・選択コピーできます。出典索引はコピー本文に含めません。CLIでも`docredock package search package.zip "売上"`、`docredock package read package.zip --part part-0001`が使えます。要確認のパッケージは終了11で本文を出さず、確認後の`--allow-review`で読み取れます。1分割では本文を絞る効果が限られ、全分割を渡すと注記の反復で全文より増える場合があります。

## 4. 内容ポリシーを選ぶ

- **visible**（既定）: 認識できる非表示テキスト、シート・行・列、スライド・オブジェクト、ノート、コメント、変更履歴のメタデータと、PDFで表示範囲の完全に外側にある文字や非表示レイヤーの文字を除外します。
- **complete**: 非表示情報とメタデータを含め、警告を出します。
- **sanitized**: メタデータ、派生・OCR情報、ヘッダー／フッター等も除外します。

Wordの変更履歴は`--revisions final|markup|reject`（GUIの「Wordの変更履歴」、APIの`Revisions`）で指定します。各ポリシーでのCLI・GUI・APIの既定値は[変更履歴の既定値](../reference/revision-defaults.md)を参照してください。`final`は削除内容・移動元・履歴注記を除外し、その除外は警告ではなく情報として記録します。`markup`は変更履歴を表示し、削除した文字を含む場合があります。`reject`は変更履歴がある文書の書き出しを拒否します。`sanitized`で`markup`を選ぶ場合は`--allow-revision-sharing`またはGUIの許可チェックが必要です。許可チェックは保存されません。履歴付き出力は共有確認対象となり、`--fail-on-review`で終了11になります。原本と復元用サイドカーには履歴が残ります。

XLSXの書き出しでは、`--sheets Sheet1,Sheet2`（CLI限定）で指定したシートだけを対象にできます。指定した名前は既存のシート名と（大文字小文字を区別せず）完全一致する必要があります。存在しない名前を指定するとexit code 2で失敗し、出力ファイルは作成されません。一部の名前だけ一致しない場合（部分的な不一致）も、その名前を黙って無視せず失敗します。指定したシートが非表示で`visible`/`sanitized`ポリシーにより除外される場合はエラーにはなりませんが、`XlsxSheetExcludedByPolicy`という警告（exit code 1）を出し、出力が空に見える理由を説明します。含めるには`--content-policy complete`を使用してください。

OCRテキストは親画像の可視性を引き継ぎます。親partitionを解決できない場合は専用の`derived-assets`へ配置し、`OcrParentPartitionUnresolved`を出します。

## 5. 結果を確認する

通常の内容に加え、図を含む文書では次を確認します。

- 見出し階層、リストの入れ子、結合表の空継続セル、数式キャッシュ警告、スライド区切り
- flowのnode label、接続方向、分岐、YES／NO等のedge label
- report上の`native-connection`と`geometry-inferred`の区別
- `VisualConnectorUnresolved`、`VisualEdgeLabelUnresolved`、`VisualSemanticProjectionPartial`等のdiagnostic
- Markdownから参照されるasset／page preview／placeholderと、元文書の同じページ・slide・sheet
- 同じtextboxやAlternateContent fallbackが重複していないこと

Warningが出た場合、MarkdownだけをAIへ渡すと意味欠落を見落とす可能性があります。diagnostic/reportとassetを一緒に確認し、必要なら元文書も参照してください。情報以外の診断がある場合と出力が空の場合、CLIは終了コード1を返します。確認項目だけでは終了コードは変わらず、`--fail-on-review`を付けたときに11になります。`--json`では`needs_attention`と`attention`がこれらをまとめて示します。抽出したのに本文から参照されていない画像は`ImageNotWritten`として報告し、確認が必要な項目に数え、「視覚要素の変換」も一部扱いにします。

閲覧用出力はpixel-perfect再現や元Office図形への完全復元を保証しません。元文書を正本として保持してください。形式別の保証範囲は[対応状況](supported-features.md)を参照してください。

## 6. 実験的PDF生成

DocRedockは日本語フォントを同梱・ダウンロードしません。ASCIIのみのPDFはBase14 Helveticaを使い、非ASCIIは次の順で埋め込み可能なTrueTypeを解決します。

1. `--font-path`と任意の`--font-face-index`
2. `DOCREDOCK_PDF_FONT_PATH`と任意の`DOCREDOCK_PDF_FONT_FACE_INDEX`
3. OSにインストールされたシステムフォント

```sh
DOCREDOCK_ENABLE_EXPERIMENTAL=1 docredock render input.md --format pdf \
  --font-path /path/to/font.ttc --font-face-index 0 --verbose
```

CFF／CFF2、グリフ不足、不正なcollection、埋め込み禁止フォントは拒否します。選択フォントのライセンス遵守は利用者の責任です。`--verbose`は選択パスを表示し、`--quiet`は情報行だけを抑制します。欠落・切り詰め警告があれば終了コード1です。

## 7. capability と PDF OCR の診断

環境の capability は doctor で確認できます。doctor は実験機能 gate の外で実行でき、入力ファイルも不要です。

    docredock doctor
    docredock doctor [--strict]
    docredock doctor --json

ready は依存関係を実測して利用可能、partial は一部の機能または OCR 言語だけ利用可能、unavailable は不足または無効化された状態です。ネイティブPDF OCRも内容によってpartialになる場合があります。画像PDFの OCR には OCR engine と PDF rasterizer の両方が必要です。rasterizer は明示パス（DOCREDOCK_PDF_RASTERIZER）、次に PATH 上の pdftoppm、mutool の順で探索します。探索を無効化する場合は DOCREDOCK_DISABLE_PDF_RASTERIZER=1 を設定します。未検出時は pdftoppm または mutool をインストールするか、実行ファイルのパスを設定してください。PDFの診断とベクターパス一覧は`report.json`に記録します。Markdown本文にはネイティブテキストと、意味のある未解決コネクタのラベル・線種注記を保持します。fallbackを圧縮した場合、reportにはページごとの総数・出力数・省略数を記録し、詳細診断はコードごとにページあたり最大10件に制限します。幅または高さが3ピクセル未満の画像（スペーサーの点や細い罫線の画像）は文字を含められないためOCRに渡さず、`OcrImageTooSmall`の情報として表示します。

**Windows で OCR を有効にする。** Windows Media OCR（ネイティブ provider。`ocr-native`／`windows-media`として報告されます）を使うには、言語ごとの OCR 言語機能が必要です。これは表示言語とは別の、任意インストールの Windows コンポーネントです。日本語を表示言語として追加しただけでは、日本語 OCR は有効になりません。実際に何がインストールされているかは `docredock doctor`（または `docredock doctor --json`）で確認できます。利用可能な言語パックが見つかると `ocr-native` は `ready` になり、`action` に不足している言語と追加方法が具体的に示されます。言語パックを追加するには、設定 > 時刻と言語 > 言語と地域 > 言語を追加 > (言語) > オプション > 「光学式文字認識 (OCR)」を使うか、管理者権限の PowerShell で `Add-WindowsCapability -Online -Name Language.OCR~~~ja-JP~0.0.1.0`（日本語）／`Language.OCR~~~en-US~0.0.1.0`（英語）を実行します。PDF rasterizer（pdftoppm／mutool）はこれとは無関係です。rasterizer が必要になるのは画像のみの PDF ページを OCR する場合だけで、DOCX/XLSX/PPTX に埋め込まれた画像の OCR や、すでにネイティブテキストを持つ PDF ページには影響しません。そのため rasterizer が未検出でも OCR トグルは無効化されなくなりました。Windows Media OCR が利用できない場合は、可搬な代替として Tesseract を導入してください（[対応状況](supported-features.md)を参照）。

各 capability には tier（`required`: docx-readable、xlsx-readable、pptx-readable、pdf-text／それ以外はすべて `optional`。OCR、PDF rasterizer、mermaid-render を含む）が付きます。素の `docredock doctor` と `docredock doctor --json` は常に同じ終了コードを返します。必須 capability がすべて ready なら 0、そうでなければ 1 です。optional な不足は出力に表示されますが終了コードには影響しません。`--strict` を付けると、optional を含めどれか1つでも ready でない capability があれば終了コード1になります。ただし、その optional な不足がすでに ready な代替手段で満たされている場合（`satisfied_by` で表示）は例外です。たとえばネイティブ OCR ヘルパーが同梱されないプラットフォームでは、Tesseract が ready になると `ocr-native` は `satisfied_by: "tesseract"` を報告し、`--strict` でもこの不足では失敗しません。`partial` な代替手段は満たしたことにはなりません。JSON レポートには既存フィールドに加えて `tier`・`satisfied_by`・`strict`・`exit_code`・`summary`（`required_ready`・`optional_gaps`・`strict_failures`）が追加されます。

PdfTableInferred は規則的な罫線から表を再構成したこと、PdfTableNative は既存表情報を利用したこと、PdfTableAmbiguous は表として一意に決められなかったことを示します。`VisualFallbackCompacted` は`report.json`のPDFベクターパス一覧をメタデータ上限に合わせて圧縮したことを示し、レポートにはページごとの総数・出力数・省略数を記録します。図の小さな欠落やノイズは未解決のまま残る場合があります。意味のあるconnectorラベルと線種注記はMarkdown本文に残し、診断はreportに記録します。

## 8. プライバシーと更新確認

変換はローカルで行います。アプリ上部には実行中のバージョンが常時表示されます。起動時に公開GitHub Releases APIからPublic Betaを含む非draftの公開版をバックグラウンド確認し、新版があれば現在版と最新版を表示します。「更新を確認」で手動確認でき、オフラインやAPI制限時も変換と起動は継続します。更新は自動インストールされず、信頼済みのGitHubリリースページから利用者がパッケージを選びます。起動前に`DOCREDOCK_DISABLE_UPDATE_CHECK=1`を設定すると自動確認を無効化できます。

実験ワークフローは[実験機能](experimental-features.md)、取り扱いは[セキュリティとプライバシー](security-and-privacy.md)を参照してください。

## 変換結果の確認と原本の保護

結果画面は「正常完了」「警告付き完了」「失敗」を区別します。警告付きでは、保存できたことと原本照合が必要なことを主表示に示し、影響ページや未解決の内容を表示します。

PDFの表・図が未解決の場合、利用可能なラスタライザで原本ページの照合画像を添付できます。この画像は原本との比較専用で、OCRには渡しません。GUIの「PDFの未解決ページに原本照合用画像を添付」、CLIの`--pdf-fallback-images auto|off`で切り替えます（既定`auto`）。画像は`.assets/`、`--embed-images`ではMarkdown内に保存します。画像を添付しても未解決警告は残ります。画像生成ができない場合はページを示す診断を確認してください。

OCRの折り畳み表示には、エンジンが返した単語または行ごとの信頼度と位置を追加しています。信頼度80%未満を「要照合」、値がない場合を「未提供」と表示し、識別子・品番・数値を自動修正しません。外部画像への位置リンクは画像の`xywh`フラグメントを含みます。領域への移動は閲覧ソフトの対応に依存し、未対応でも位置座標と原画像を比較できます。Visionの座標は左下原点の正規化座標で表示し、リンクでは左上原点の百分率に変換します。

OCR照合情報は本文と同じ行順・行内の左右順で表示し、行番号を付けます。Readableの既定は信頼度80%未満または信頼度不明の詳細だけです。GUIの「OCR照合情報の詳細」、CLIの`--ocr-review low-confidence|all|summary`で切り替えます。`all`は全件、`summary`は件数だけを表示し、OCR本文と原画像はどの設定でも保持します。audit／roundtripのサイドカーには全件を保持します。信頼度はエンジンの推定値であり、正解率ではありません。

識別子・日付・金額を信頼度にかかわらず原本と照合するには、`--ocr-review all`を使います。Tesseractが指定言語を読み込めない場合、書き出しは`OcrLanguageUnavailable`を通知し、JSONの診断には`requested_languages`、`missing_languages`、`used_languages`が入ります。不足言語データを入れて再実行してください。`--ocr-strict`を指定すると、出力を保存したうえで終了コード8を返すため、OCR本文を渡す前に自動処理を止められます。

書き出し集計の`Fallback pages`はベクターパスのフォールバックがあるページ数です。`Pages requiring review`（要確認ページ数）、`Review image pages`（照合画像添付ページ数）、`Unresolved visual elements`（未解決の図形・接続・ラベルの数）を別に表示します。画像を添付しても要確認の件数は減りません。未解決要素は同じパスとその接続を重複して数えません。PDFの診断とパス一覧は`report.json`に記録し、fallbackを圧縮した場合はページごとの総数・出力数・省略数も記録します。

書き出し集計の先頭には、性質の異なる結果を別々の行で表示します。`Output written`はMarkdownを保存できたこと、`Visual elements converted`は認識した図形・線・ラベルをすべてMarkdownで表現できたか（`all`）、一部が未解決か（`partial`）、`Detected review items`は検出された要確認事項（図の要確認ページ数、解析できなかった内容のあるページ数、OCRの確認件数、Excelの表の区切り）で、なければ`none`です。`none`は「検出された事項がない」という意味で、変換結果を検証したことを意味しません。読み順と表の構造をどう得たかは`Reading order`と`Table structure`の行に示します。原本の構造をそのまま使った場合（Wordの本文順、Word・PowerPoint・グラフの表、タグ付きPDFの表）は`source order`／`source tables`、DocRedockが位置やセル配置から組み立てた場合（PDF・スライドの読み順、Excelの表、罫線から組み立てたPDFの表）は`inferred from layout (not compared with the source)`、表の構造の一部を判断できなかった場合は`… boundary(ies) need source comparison`、表がない場合は`no tables`、編集用（往復）の書き出しでは`not evaluated`です。GUIでは「検出された要確認事項: なし／読み順: 原本の順序／表構造: 配置から推定（原本とは未照合）」のように1行で表示します。`all`は色や線の太さなどDocRedockが扱わない属性の保持までは意味しません。2行目の`Unanalyzed content`は、ページが描いているのに中身を解析できなかった部品（PDFのForm XObjectなど）の件数とページ数です。`Visual elements converted: all`は認識できた要素についての結果なので、`Unanalyzed content`が`none`以外ならページ全体の解析は完了していません。続けて要確認ページごとに`Review page 1: 1 diagonal line(s) across a table …; review image: …`のように、何を確認するか（斜めの線・矢印、接続先が未確定の線、どの線の説明か確定できない文字、図として再構成できない図形、解析できなかった描画部品）と照合画像の場所を1行で表示します。件数は診断レコード数ではなく、確認する要素とページの数です。

`complete`で非表示内容を含めた場合は、`Detected review items`に`hidden content included - review before sharing`（共有前に内容を確認）も表示します。原本との照合事項がある場合はその後に続けます。この確認によって要確認ページや照合画像の件数は増えません。`HiddenContentIncluded`警告による終了コード1は従来どおりです。

Excelの表のすぐ上で、先頭の列に1つだけ書かれた文字（`売上実績（単位: 千円、税抜）`や`対象: 国内全店`のような表題・単位・条件の注記）は、表の上の文として出力します。何行あっても表の見出しにはならず、見出し行をデータへ押し下げることも、2列の表を「キー: 値」の箇条書きに変えることもありません。2列の場合は、見出し行のすべてのセルが強調（太字・塗りつぶし・中央揃え）されているときに適用します。値が空の見出し語が続く欄は文書情報として扱うためです。

Excelの1列の空白は、1つの表の中の区切りのこともあれば、2つの表の境界のこともあります。片側が隣の行の値だけ（IDと数量、行見出しと数値）か備考の列なら1つの表として保ち、両側がそれぞれ自分の見出し・ラベルを持つ場合は、一方の行を他方の行として見せないよう別の表に分けます。値だけの範囲でも、数値から隣の表と行がずれているとわかる場合（自分の見出しが隣の表の数値の横にある、値が隣の表の数値の見出し行の横から始まる）や、先頭の列が期間（年・月・日付・Yearなど）の見出しで一定間隔の期間が並び、隣の表にも数値がある場合は、独立した表として扱います。文字だけの列の横では、期間の列は1つの表の行のキーとして扱います。数式の結果の文字は、数式に書かれた固定の語（=IF(…,"達成","未達")）の場合だけ値とみなし、参照・検索した文字や他のセルから組み立てた文字（='月次分析'!H5、VLOOKUP、=B2&" "&C2）は入力された文字と同じく扱うため、名称はラベルになります。下へコピーした数式も同じように判断します。空白列を挟まずに接する表は、それぞれが自分の結合タイトルの下にあり（下のセルは結合なし）、どちらも先頭の列がラベルで、構成が異なる場合（一方だけがExcelのテーブル、または一方は見出し行を持ち、同じ行から始まるもう一方は各行の先頭のセルを強調したラベルで示す凡例の形）に分けます。書式の違いだけでは分けないため、1つの表の列をまとめる見出し（2024年 | 2025年、担当者 | 連絡先、作業一覧の横の日程）の下は1つの表のままです。Excelのテーブル（ListObject）として定義された範囲がある場合はその範囲に従います。両側がまったく同じ行を占め、配置から判断できない場合は、分けたうえで照合の対象として示します。CLIの`Review sheet 'Data': cells on either side of blank column C (A1:B3, D1:D3) were output as separate tables; …`、情報診断`XlsxTableBoundaryAmbiguous`、`Detected review items`の`table boundaries N`、Markdownの`<!-- inferred: … -->`注記、GUIの「表の区切りの確認 N件」です。OCRの確認と同じく、終了コードは変わりません（`--fail-on-review`を付けた場合は11）。

取り消し線を引いた文字は、表の中を含め、出力するすべての場所で`~~文字~~`として取り消し線を保ちます。取り消した値を有効な値として読まないためです。対象は、Excelのセルの書式と一部だけ取り消したリッチテキスト、Wordの取り消し線と二重取り消し線、PowerPointのテキスト（WordとPowerPointの表のセル内も含む）です。PDFの取り消し線は文字の上に引かれた線です。線の下の文字と、注釈の取り消し線（StrikeOut）の下の文字に、取り消し線の印を付けます。フォントが字幅を持つ場合（埋め込まれたフォントの多く）は、線が1つのテキスト描画単位（Excel、LibreOfficeなど多くの作成ソフトは書式の区切りごとに分けて書きます）の一部だけに掛かっていても、線の下の文字だけに印を付けます。字幅を持たないフォント（字幅を書かずに使った標準のフォントなど）で、線が描画単位の一部だけに掛かる場合は、どの文字かを判定できないため、印を付けずに出力し、警告`PdfStrikethroughUnplaced`を出したうえで、Markdownのその位置に原本との照合を求める注記を置き、そのページを要確認として数えます（`--fail-on-review`の対象です）。PDFに引かれた下線（破線で引いたものを含む）や取り消し線は文字の書式として扱い、図の線にはしません。文字の大きさの半分より高い位置に引かれた線（上線）や、すぐ下に別の文字がある線（分数の線など）は、取り消し線や下線とはみなさず図の線として残します。短い線分を並べて描いた破線の罫線は1本の罫線として扱うので、そうした罫線の表も実線の表と同じように表として出力します。

下線を引いた文字は`<u>文字</u>`として出力します。Wordの段落とPowerPointのテキストに加えて、Excelのセルの書式と一部だけ下線を付けたリッチテキスト（一重・二重・会計用）、WordとPowerPointの表のセル、Wordのヘッダー・フッター・脚注・文末脚注・テキストボックス、PDFで文字の下に引かれた線（実線・二重線・破線・点線・波線）と注釈の下線（Underline・Squiggly）が対象です。取り消し線と下線の両方がある文字は`<u>~~文字~~</u>`になります。リンクの書式としての下線と、PDFで表の行の下に引かれた罫線は強調ではないため印を付けません。見出し、表題、Excelの表の列名には下線の印を書きません。PDFで字幅を持たないフォントの描画単位の一部だけに引かれた下線は、どの文字かを判定できないため、印を付けずに出力します（下線は強調なので要確認にはしません）。

文字を取り消すために文字の上に重ねて引いた直線や、強調のために文字の下に引いた直線（図形の線）も、図ではなく文字の取り消し線・下線として扱います。対象は次のとおりです。

- Excel：セルの上に描いた線や細い棒（値や行全体を貫く赤線・二重線）
- PowerPoint：テキストボックスや図形の文字、表のセルの上の線
- Word：表のセルや、1行に収まる段落に固定された線（段落と段・余白を基準にした位置）
- PDF：文字からはみ出して手で引いた線、直線の注釈（Line）、1本のまっすぐな手書きの注釈（Ink）

線が文字の一部だけに掛かって、どの文字を取り消しているかを判定できない場合は、取り消し線の印を付けずに出力し、その位置を原本との照合が必要な箇所として数えます（`--fail-on-review`の対象です）。下線の場合は印を付けずに出力するだけです。塗りのある図形や表のセルの下に隠れた線は、その上の文字の装飾とはみなしません。矢印、図形どうしをつなぐコネクタ、空のセルの上の線は、従来どおり図や表の記号として扱います。Wordでは、ページや余白を基準に縦位置を決めた線、複数行の段落、行グリッド（日本語の既定の書式）に沿って配置される段落の上の線は、文字の位置を確定できないため図として残します。

OCRの確認件数（信頼度80%未満または信頼度不明の認識結果の数）は警告とは別に`OCR summary: images=…; regions=…; review_items=…; review_required=true|false`と表示します。OCRの確認が必要でも、それだけでは警告にならず終了コードは変わりません。GUIでも「OCR確認 N件」を警告とは別の行に表示します。

`export --json`で変換前に一括処理を中止した場合も、フォルダーから展開したファイルを含め、特定できた入力ごとに失敗結果を返します。引数エラーで入力を特定できない場合は、空の`results`と、`code`、`message`、`exit_code`を持つトップレベルの`error`を返します。

ブックに再計算待ちが記録されている場合は、Excelの再書き出しでも`XlsxRecalculationRequired`が出て、AIパッケージは要確認になります。数式の結果を使う前に、Excelで再計算して保存し、書き出し直してください。保護された画像のリンク先を変更すると、`preflight`と`restore`は`ProtectedNodeEdit`で拒否します。

GUIの結果画面は、主表示に「要確認 1ページ／照合画像 1ページ添付／未解決の線・図形 1件」のような件数と、「1ページ目：表の上の斜めの線1件を表の記号に変換できませんでした。表の文字は書き出されています。照合画像で線の意味を確認してください。」のような短い説明を表示します。診断コード、内部ID、信頼度は「詳細（診断コードと対処）」に折りたたんで表示し、同じ未解決要素から生じた関連診断は1項目にまとめます。「該当ページを確認」を押すと、原本のページ画像（未解決の線・図形を赤い線と枠で強調。解析できなかった描画部品は、それが描かれうる範囲を、文字の対応や表示の有無を確定できなかった文字はその位置を、赤い破線の枠で表示）と、そのページのMarkdownを並べた照合画面を開きます。「要確認箇所へ拡大」を押すと強調した箇所を1件ずつ画面中央に拡大し、「＋」「－」（Ctrlキー＋マウスホイールも可）で倍率を変え、「全体」でページ全体の表示に戻ります。赤い線と枠は拡大しても画面上の太さが変わらず、「強調表示」のチェックを外すと消えるので、位置を確かめた後に原本の細部を確認できます（ページを切り替えても設定は保たれます）。右側のMarkdownは、表を罫線付きの表、Mermaidの図を「START → END（ラベル）」のような接続の一覧で示す「表示」と、Markdownそのものの「ソース」を切り替えられます（読み取れないMermaidはソースのまま表示）。照合画像がない場合（rasterizer未構成、添付オフ、Office形式）は、原本の該当ページを開くよう案内します。内容ポリシーで除外した非表示の内容（Wordの非表示文字、PDFの表示範囲外の文字など）がある場合は、結果画面にその種類と件数を表示します。

復元前の統合チェックは、作業領域のコピーで実際の復元を試します。元文書・Markdown・サイドカー・既存レポートは変更しません。

```sh
DOCREDOCK_ENABLE_EXPERIMENTAL=1 docredock preflight edited.md
DOCREDOCK_ENABLE_EXPERIMENTAL=1 docredock preflight edited.md --json
```

`verify`は整合性、`diff`は編集内容、`preflight`は整合性と編集検出と試験復元を確認します。正常な編集の検出だけでは警告終了になりません。`verify`は編集されたことを「Projection: edited since export」と表示し、終了コード0を返します。Excelでは、編集したセルを数式が参照しうる場合と、編集で数式を書いた場合だけ、`preflight`と`restore`が`XlsxRecalculationRequired`で警告し、該当する数式セルを示します。これらのセルの保存済みの計算結果は、Excelが再計算するまで編集前の値のままです（DocRedockは数式を計算せず、開いたときに再計算するようブックに設定します）。0.3.10で書き出した、表の範囲が重なるMarkdownも編集できます。セルの所属を判別できない場合は`SpreadsheetGridOverlap`で書き出し直しを求めます。終了コードは0が復元可能、1が警告付きで復元可能、3がサイドカー不整合、6が編集を復元できない状態です。編集済みPDFの再生成を許す場合は`--allow-render-fallback`を明示します。成功は対応範囲での復元可能性を示し、Officeでの外観の一致を保証するものではありません。

元のOfficeファイルを復元先に指定しても、通常の`--force`だけでは置換できません。元文書を置き換える場合は`--force --replace-original`を指定します。復元に成功した後、置換直前のファイルを`<出力名>.docredock-original-<ID>.bak`に保存してから置換します。通常は別名の出力先を推奨します。
