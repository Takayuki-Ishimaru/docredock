# PDF visual-review corpus

All PDFs in this directory are synthetic fixtures created for DocRedock.
They contain no customer documents, personal data, credentials, or
production identifiers.

## complex-layout.pdf

`complex-layout.pdf` is a deterministic, layout-heavy PDF corpus (multi-column
text, tables, embedded images) generated by `generate_complex_pdf.py` and used
by the extraction/readable-conversion regression tests.

## schedule-arrows.pdf (PDF table-overlay fixture)

`schedule-arrows.pdf` is the PDF twin of `../Pptx/schedule-arrows.pptx`,
`../Xlsx/schedule-arrows.xlsx`, and `../Docx/schedule-arrows.docx`: the same
Japanese IT-project schedule table drawn with ruled-line grid graphics, with
arrow/bar/marker/today-line vector shapes painted on top of it, used to test
the PDF "table overlay" extraction feature. It is generated by
`generate_schedule_pdf.py`, which is dev-only (not part of the build, not
required to run the test suite — the checked-in `.pdf` is the regression-test
authority). Like `generate_complex_pdf.py`, it draws Japanese text with an
embedded (subset) TrueType font resolved by that script's `resolve_font()`
helper (a system Japanese font, or `DOCREDOCK_PDF_FONT_PATH` /
`DOCREDOCK_PDF_FONT_FACE_INDEX`) rather than the non-embedded, predefined-CMap
`HeiseiKakuGo-W5` CID font it used previously — DocRedock's BCL-only PDF text
extractor cannot decode that CID encoding, which made every label extract as
mojibake even though it rendered correctly on screen. Regenerate with:

```
python3 tests/DocRedock.Tests/Fixtures/Pdf/generate_schedule_pdf.py \
    tests/DocRedock.Tests/Fixtures/Pdf/schedule-arrows.pdf
```

Add `--verify` to re-check an already-generated file without rebuilding it.
